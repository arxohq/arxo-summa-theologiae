# Delivery and limits

This is a fresh-history consumer export, not a clone of the private corpus. The assigned scope is 27 Summa treatises and the separate double-effect package. No model npm package, new model semantics, website or MCP service is part of this delivery.

`source-pin.json` records the corpus commit and the exact selected working-tree bytes. Per-file hashes identify the captured source; the commit alone does not claim that dirty inputs were already committed. Original model and case bytes are retained. Generated additions are fresh `law.core/0.2.11` CLIR, package locks, native requests and answers, and consumer documentation.

The moral kit's `00-imports.law` is dependency binding only, without subject rules. Its current lock and `deps/` are generated from the selected double-effect model. The authoring evaluator, oracle and private check scripts are not copied. All theological/moral evaluation belongs to the published Arxo CLI.

`toolchain.lock.json` records @arxo/cli 0.2.4 and the two exact platform packages with binary and archive hashes. They are ordinary published npm packages, not a custom Summa runtime.

Depth uses the existing corpus `boundaries.depth` implementation on captured original division declarations. The recorded applicability helper is an existing captured lawref implementation used for measurement only; it is an explicit override of the corpus's unavailable unpublished runtime lock, not a fresh lawref/runtime acceptance claim. Implementation hashes are retained. Public readers can verify the input/report hashes; reproducing the classifier requires those maintained implementation inputs. No second classifier is implemented here.

Every article-level count is structural. Admitted sed-contra leaves, guarded applied heads and preserved proof texts do not imply that the complete philosophical derivation is machine checked. Original audits and catalog claims remain historical; only the current verification report describes this CLI run.

The exact allowlist exporter is the existing `canon_publication.py`. From a fresh checkout:

```sh
python3.12 tools/canon_publication.py export --source . --config publication.toml --out /tmp/arxo-summa-artifact
python3.12 tools/canon_publication.py verify --artifact /tmp/arxo-summa-artifact
```

Use a new output directory. The publication inventory excludes Git history, caches, build products, node_modules and private authoring tools. Source and evaluation hashes are different identities; the original lowerer semanticHash placeholder is not substituted for a measured raw-world or package artifact hash.

Full corpus `not_checked`; releaseVerified false. Historical source notices record the owner's earlier public-reader decision and are preserved. No modern translation or publisher HTML shell is added to the exported Latin text witnesses.

## v0.2.0: additive argument reconstruction kit

The original v0.1.0 reader and its 28 models remain byte-identical for source,
case and registry inputs. Seven new independent experimental packages live in
`reconstruction/`; their model versions are 0.1.0 and semantics law.core/0.2.11.
They introduce subject reconstructions without changing Arxo core or the SDK.

`reconstruction/export-origin.json` identifies the captured corpus source tree,
exact original file bytes and intentional public documentation/runner adaptations.
Compiled IR and 13 native reader examples come from the checked authoring runs;
no private machine path is required to execute them. The original acceptance
report is historical authoring evidence with `published: false`. The separate
public verification report and CI artifacts identify delivery checks.

The default CI scope checks 73 new scenarios and 132 native queries twice on
Linux x64, the protected-input guard, 13 retained reader examples, and the original
reader example replay. It checks all supplied hashes and exports the exact
allowlisted archive through the existing exporter. It does not repeat the 294
unchanged original scenarios or run the full corpus. A supplied matching release
tag publishes that verified CI archive and its SHA-256 through GitHub Releases.

There are 21 checked finite fragments, 22 conditional obligations, 32 source
reconstructions and 15 unsupported obligations across 90 project-defined entries.
No whole article is fully verified. Public delivery does not promote these
statuses or imply a formal checker certificate. Full corpus remains not_checked
and releaseVerified remains false.
